# 操作性・戻るジェスチャーの実装契約

対象: 懸賞Pocket v1.0 / 最優先要件

## 1. 原則

Androidの標準ナビゲーションを採用し、「戻る」は同じアプリ内のNavigation Back Stackを操作する。画面端に独自のスワイプ検出Viewを重ねない。古いonBackPressedの直接オーバーライドや独自の画面履歴配列で全画面を制御しない。

通常の画面遷移はNavigation Composeに委譲する。例外的な入力保護やモーダルには、その時点で必要な範囲だけ対応済みBack APIを使う。Activityのルートで常時戻るを横取りしない。これにより標準のPredictive Backやホーム復帰の動作を妨げない。[S01]

## 2. 戻る操作の一覧

| 入力 | 必須動作 |
|---|---|
| 画面左端の戻るジェスチャー | 適切な直前画面へ。端末の対応に従う |
| 画面右端の戻るジェスチャー | 左端と同じ戻る先。端末の対応に従う |
| 3ボタンナビゲーションの戻る | 同じ優先順位で閉じる／戻る |
| 上部の戻る矢印 | 同じアプリ内戻り先へ。下書き保護も共通処理 |
| ボトムシートの下スワイプ | シートだけを閉じる。背後の画面は戻さない |
| ブラウザからの戻る | 起動元の一覧位置／詳細へ戻り、応募確認の条件を評価 |
| 通知から開いた詳細の戻る | 既存スタックがあればそれを保持。新規起動なら今日画面へ |
| 共有取込画面の戻る | 下書きを保護して入口Activityを終了。呼出元のある場合はOSに戻り先を委ねる |

Predictive Backの対応アニメーションはOSとライブラリの対応範囲で実装する。未対応のOSでも基本の戻るは動作させる。全OSで同一のプレビューアニメーションを表示すると保証しない。

## 3. 戻るの優先順位

OSが扱う現在のウィンドウ／IMEの動作を尊重した上で、アプリ内では次の順序とする。

1. 入力キーボードが開いている場合は、最初のシステム戻るでキーボードを閉じる。
2. 最前面のダイアログ、ボトムシート、画像ビューアがあれば、その対象だけを閉じる。
3. 複数選択モードや展開検索を終了する。リスト位置を維持する。
4. 編集画面では下書きの保存状態を確認し、通常の戻り先へ移動する。
5. 詳細や設定の子画面では1階層だけ戻る。
6. メインタブのルートで「今日」以外にいるときは「今日」へ戻る。タブを渡り歩いた履歴を順番にたどらない。
7. 「今日」のルートではOSへ委譲する。独自の「2回押して終了」や終了確認を常時出さない。

上部矢印は通常のアプリ内Upとして同じ親へ戻す。IMEを閉じるだけの挙動が自然でない場合、矢印はIMEを閉じた上で親へ移動してよい。ただし下書き保護と最終的な戻り先はシステム戻ると矛盾させない。この違いを独自の別スタックで実装しない。

同時に複数のBackHandlerが有効になって二重popしないよう、画面状態ごとの所有者を明確にする。モーダルの標準ハンドラーとアプリ独自のハンドラーを重複させない。

## 4. Predictive Backと下書き

### 4.1 保存済みの通常画面

NavHostへそのまま委譲する。戻りジェスチャーの進行に合わせて戻り先をプレビューでき、途中で指を戻したら現在画面に留まる。

### 4.2 入力中

編集内容はViewModel＋SavedStateHandleに即反映し、RoomのDraftへ短い間隔で保存する。初期案は300msのdebounce。画面には必要に応じて「下書き保存中／下書き保存済み」を表示する。

DBの保存済みrevisionと最新入力revisionが一致していれば、通常の戻るを妨げない。未保存・保存中・保存失敗の場合に限り入力保護ハンドラーを有効にする。

入力保護ハンドラーは対応版のPredictiveBackHandler等を用い、ジェスチャーを最後まで完了した時点でのみ、最新Draftの保存を確定してpopする。途中キャンセルでは画面遷移、破棄、応募登録を行わない。自然なアニメーションを損なう独自実装が必要になる場合は、まず下書き保存タイミングを改善する。

保存は小さなローカル処理として非同期に実行する。失敗・長時間化時は入力を保持し、画面から無言で離れない。「再試行」「内容をコピー」「破棄して戻る」を出す。「破棄して戻る」は明示確認を行う。

任意の瞬間の電源断や強制終了で最後の未永続化文字まで保存できるとは保証しない。保存済みの下書きを確実に復元し、ユーザーに保存状態が分かるようにする。

### 4.3 明示破棄

「編集を破棄」を選んだ時だけ確認を出す。既存Campaign本体は触らず、そのDraftのみ削除する。候補取込でも原文と編集済み候補をDraftとして復帰できるようにする。

## 5. タブ・画面状態

タブ切替にはlaunchSingleTop／saveState／restoreState等の標準機構を使用し、同じルート画面を何枚も積まない。実装バージョンに適した公式APIへ置き換えてよい。

各一覧で次を保存する:

- 検索キーワード、フィルター、並び順。
- 最上部に見えていたレコードIDとスクロールオフセット。
- 展開中の折りたたみセクション。
- 選択中カレンダー日、月。

応募済み操作などで起点カードがフィルターから消えた場合、周辺カードをアンカーにし、一覧先頭へ跳ねない。レコードが削除済みなら安全な空状態を出す。

プロセス再生成ではルートと必要なIDだけをSavedStateから復元し、最新データをRoomから読む。大きな画像や全文をNavigation引数へ入れない。

## 6. ブラウザからの復帰

起動直前に戻り先route、リストアンカー、LaunchSession IDを保持する。外部アプリへの移動が観測された後の復帰だけを確認対象にする。

復帰直後に一覧を再取得して先頭へ戻す処理は禁止。最新状態の差分だけを反映する。

確認用のボトムシートは「応募済みにする」「まだ」「あとで確認」。シートの戻る／下スワイプは「あとで確認」と同じ扱いで、応募済みにはしない。

当日・前日が変わっていた場合は応募日／時刻を選ぶ欄を出す。通常ケースでは余計な入力を増やさない。ブラウザに行くたび毎回URL安全確認を挟むのではなく、通常の確認済みHTTPS URLは1タップを守る。未確認OCR URLやHTTPなどの例外に限定して確認する。

## 7. 通知・共有からの入口

### 7.1 通知

内部の明示Intentには対象IDとアクションIDだけを入れ、通知外部から任意URLを注入させない。対象が消えていたら「この項目は削除されています」と今日画面への導線を示す。

アプリが終了していた場合は `今日 → 詳細` の自然な戻り先を構成する。アプリがすでに開いている場合は現在のスタックと下書きを破棄しない。新しい通知操作は保存処理後に処理し、必要なら保留する。

通知アクション「応募ページへ」はユーザーの明示タップを起点としてMainActivityが開き、詳細を戻り先にして外部ページへ進む。同じIntentの再配送で二重に開かない。

### 7.2 共有

ShareImportActivityは取込に必要な最小UIを表示し、メイン画面の二重起動を避ける。クリップボード監視はしない。共有データは直ちに内部へ安全にコピーする。

保存完了ボタンの初期ラベルは「保存して戻る」。追加の「一覧を見る」も設けてよいが、勝手に共有元とメインを行き来させない。

取込中に別の共有が届いた場合、既存の未保存内容を上書きせず、新しいImportSessionとして待機させる。直前の同一Intentが画面回転で再処理されないようセッションIDを復元する。

## 8. 片手操作と誤操作対策

スマートフォンの主要アクションは下部付近へ置く。登録／編集の保存、詳細の応募ボタンはスクロールの末尾まで探さなくてよい。システム下端とIMEのinsetsを考慮する。[S12]

タップ領域は48dp以上。アイコンだけでなく読み上げラベルを付ける。本文を小さくして多くのカードを詰めるより、不要情報を閉じる。主要操作に長押しやスワイプを必須としない。[S02]

一覧の横スワイプはv1では原則使わない。戻るジェスチャーとの競合と意図しない削除を避け、カードのメニューへ集約する。画像拡大画面だけはピンチ拡大とパンを実装してよいが、左右端の戻るを不必要に占有しない。

長押しは複数選択のショートカットとして提供してよい。同じ操作をメニューの「選択」からも使える。スクロール中のタップで応募ページが勝手に開かないよう標準クリック判定を使う。

## 9. 破壊的操作

カードのメニューに「アーカイブ」を置く。履歴は削除しない。アーカイブ解除を用意する。

削除はゴミ箱へ移動し、既定では自動完全削除しない。元に戻すSnackbarとゴミ箱からの復元を用意する。削除時には対象の応募履歴・当選履歴の件数を示す。

完全削除はゴミ箱内のみ。関連データを表示して確認を取り、トランザクションで処理する。当選履歴を保持したい場合は、先に懸賞から関連解除して単独記録へ移せるようにする。

バックアップ置換復元や全データ消去は、通常の保存ボタンと近接させない。複数回の高速タップで二重実行しない。

## 10. アクセシビリティ・表示

ライト／ダーク／システムに従うの3つ。初期値はシステムに従う。読みやすさを優先した落ち着いた配色を採用し、赤と緑の区別だけに状態を依存させない。

200%の文字サイズ、TalkBack、横画面、分割画面、ジェスチャーナビと3ボタンナビ、アニメーション無効時を試験する。文字が大きい場合は行を増やし、最低限の重要情報を省略しない。

TalkBackでカードの名前・締切・状態・応募ボタンを独立して理解できるSemanticsを付ける。画像の説明、エラーの読み上げ、フォーカス移動を実装する。

## 11. 不合格となる例

- 端からスワイプしても動かず、上の矢印しか使えない。
- 入力途中の戻るで内容が消える、または変更前の本体を勝手に上書きする。
- ジェスチャーを途中でキャンセルしたのに保存・削除・画面遷移が確定する。
- ボトムシートを閉じたつもりでアプリが終了する。
- ブラウザから戻るたびホーム先頭へ戻る。
- タブを行き来するたび同じ画面が履歴に積まれる。
- ホームの戻るを空処理で消費してアプリを離れられない。
- 通知から開いた後、戻る先が空白になる。
- 画面下のボタンがジェスチャーバーやキーボードに隠れる。
- 見た目は完成していてもタップの処理が空、仮実装、常にエラーになる。

これらは見た目の好みの問題ではなく、リリースを止める機能不具合として扱う。
