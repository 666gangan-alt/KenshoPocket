# 受け入れ試験 — 100項目

対象: 懸賞Pocket v1.0

> この一覧は試験仕様。現時点でアプリ試験を実行したという意味ではない。
> 各項目をPASS / FAIL / NOT_RUN / BLOCKEDで記録し、未実施の既定値はNOT_RUNとする。

## 試験環境

最小API 26、通知権限を扱うAPI 33、API 34または35、主対象のAPI 36で確認する。実装時点で36より新しい安定版を採用する場合はその環境も追加する。少なくとも実際に利用するAndroid端末1台で、ジェスチャー、ブラウザ往復、画像、通知、再起動、更新を確認する。

Predictive Backのジェスチャー完了と途中キャンセルは、戻るボタンの自動押下だけで代替しない。OSの制限下では実際の結果を記録し、制限による遅延を未対応不具合と混同しない一方、未確認を合格にしない。

## fixtureの照合契約

`testdata/*.json`は実装前の入力例と期待値であり、完成済みのテストコードではない。Codexが対応するテストクラスとDTOを作る。期待値に列挙したフィールドだけを照合し、追加の妥当な警告は許可する。全候補の確認フラグは既定false。URLは架空であり、実通信しない。

`reminder_cases.json`のoperationごとに、通知計画・周期計算・配信判定を独立させる。SKIPPED理由は内部ではstateとreasonに分割してもよい。統計の割合表示は小数1桁四捨五入、分母0は「—」を試験上の基準とする。

## リリース判定

戻る不能、データ消失、誤った応募済み、未確認日付の確定、締切後の誤通知、復元破損、セキュリティ検査回避はリリース阻害。環境不足の実機試験が残る場合は、検証待ち版として扱い、その範囲を明示する。
