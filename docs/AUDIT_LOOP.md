# 開発・デバッグ・監査ループ

## 目的

KenshoPocketの変更を、実装担当と独立した読み取り専用の監査役で短いループに通す。監査役は仕様違反、データ消失、安全性、通知境界、テスト不足を優先して指摘し、実装担当は指摘を1件ずつ修正して再検証する。

## 役割

- 実装担当: 小さな変更を行い、回帰テストを追加し、ローカル監査とGitHub Actionsを確認する。
- 監査役サブエージェント: 共有ワークツリーを変更せず、仕様・コード・テスト・CIを独立に読み、重大度、再現手順、受け入れ基準を返す。
- リリース判定: 戻る不能、データ消失、誤った応募済み、未確認日付の確定、締切後の誤通知、危険URLの起動、復元破損は阻害として扱う。

## 1サイクル

1. `git status --short` と直近コミットを確認し、対象範囲を固定する。
2. 監査役が読み取り専用で現状と再現手順を記録する。
3. 実装担当が最小の修正と回帰テストを追加する。無関係なリファクタリングはしない。
4. `pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/audit.ps1`、該当するGradleタスク、`git diff --check`を実行する。
5. 監査役が変更差分を再確認し、指摘が解消されたか判定する。
6. ローカルJDKがない場合は`BUILD_BLOCKED`として記録し、GitHub Actionsで同じcommitを検証する。未実行をPASSにしない。
7. CIが成功した場合だけ、結果・Artifact・未検証項目を`docs/TEST_REPORT.md`と`docs/IMPLEMENTATION_STATUS.md`へ反映する。

## 6時間の進め方

作業時間は、次の順に区切る。各区間の終了時に監査役から再判定を受ける。

- 0:00–0:30: 現状監査、再現確認、優先順位付け
- 0:30–2:00: データ保持・URL安全性・通知境界などリリース阻害の修正
- 2:00–3:30: 回帰テスト、migration、共有取込と応募確認の統合確認
- 3:30–5:00: UIの未接続導線、文言、状態復元、アクセシビリティの静的確認
- 5:00–6:00: CI再実行、Artifact確認、監査報告と残課題の確定

6時間経過後も実機が利用できない場合、実機試験は`NOT_RUN`または`BLOCKED`のままにし、完成とは呼ばない。バックグラウンドで継続すると約束せず、次のサイクルに引き継ぐ。

## 合格条件

- 変更対象の自動テストがPASS。
- `lintDebug`と`assembleDebug`が成功する（ローカル不可なら同一commitのCI成功）。
- 監査役の重大度High/Critical指摘が0件。
- `git diff --check`が成功し、秘密情報・署名鍵・ローカル設定を追跡していない。
- 実機、通知、Predictive Back、OCR、復元など未実施項目が明示されている。
